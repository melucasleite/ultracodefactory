# Security

## What Ultra Code Factory does on your machine

Ultra Code Factory is a launcher and viewer for AI coding agents. It:

- reads and writes markdown cards in each project's `.codefactory/` folder (or
  the cards folder you chose for it), and creates new project folders only
  when you finish the New Project wizard;
- starts `claude` (Claude Code) in the repository folders you choose, either
  headless (`claude -p`) or inside a detached `tmux` session;
- reads those tmux sessions' screens and sends them the keystrokes you type
  or click;
- stores a job ledger and agent logs in
  `~/Library/Application Support/Ultra Code Factory/`, with logs readable only by
  you (mode 0600).

It makes **no network connections of its own**, collects no telemetry, and
stores no credentials. Agents it launches use your existing Claude Code login
and settings.

## Why the app is not sandboxed

The App Sandbox would prevent the app from running `tmux` and `claude` in
arbitrary folders, which is its core job. The app ships with the hardened
runtime instead, and is signed ad hoc by default.

## Agent permissions

Agents run with the permission mode you choose in **Settings → Agents**. It
is passed to Claude Code as `--permission-mode`:

| Mode                        | What the agent may do without asking                    |
| --------------------------- | ------------------------------------------------------- |
| Ask for everything          | nothing                                                 |
| Accept file edits (default) | edit files; shell commands still need approval          |
| Plan only                   | read only                                               |
| Bypass all permissions      | **anything**, including deleting files and pushing code |

Headless agents can't answer permission prompts, so anything their mode
doesn't allow is refused. Only use **Bypass all permissions** in disposable
repositories, ideally inside a container or VM.

Agents read card text and repository contents, so a malicious card or
repository can try to steer them (prompt injection). Treat cards from
untrusted sources the way you would treat untrusted code.

## Folders outside the repository

Agents run inside the project's repository and Claude Code refuses file access
outside it. When a headless agent is refused, Ultra Code Factory lists exactly
what was refused and offers **Allow & Re-run**, which adds the folder to the
project's **Allowed Folders** (passed to Claude Code as `--add-dir`). You can
review or remove allowed folders from the project's right-click menu. A cards
folder that lives outside the repository is allowed automatically.

## Hardening in the code

- Every process is started with an argument array (`execve`), never through a
  shell. Prompts and typed text cannot be read as shell syntax.
- Text sent to tmux uses `send-keys -l --`, so words like "Enter" are typed
  literally. Named keys come from a fixed allow-list.
- Project, status and card names are validated as single path components
  (no `/`, `\`, `..`, NUL or leading dot) before any filesystem access.
- tmux session names are generated by the app and validated against
  `[A-Za-z0-9-]`.
- Before stopping a headless agent, the app checks that the PID is still
  alive, started after boot, and still running the agent executable, so it
  never signals an unrelated process that reused the PID.
- Moving a card never overwrites an existing file, and deleting a card moves
  it to the Trash.

## Reporting a vulnerability

Please report security issues privately through GitHub's
[private vulnerability reporting](https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing-information-about-vulnerabilities/privately-reporting-a-security-vulnerability)
on this repository rather than in a public issue.
